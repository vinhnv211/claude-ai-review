AI Review Framework v0.1.0

Multi-agent code review framework cho dự án embedded (router / wifi AP / camera IP)

Giới thiệu

AI Review Framework là hệ thống review code sử dụng nhiều AI agent phối hợp, thiết kế cho các dự án embedded: router, wifi AP, camera IP, set-top box. Framework cover: code C/C++ (source + kernel driver), shell script (POSIX/ash/bash + OpenWrt idioms), WebGUI (HTML/JS/CSS/Lua/LuCI/CGI), và OpenWrt build infrastructure (Makefile/patches/overlay/tarball).

Phiên bản v0.1.0 — stable release đầu tiên
  • 8 review agents: dhcp, pppoe, tr069, mesh, wifi-driver, web, openwrt-build, generic
  • 8 core skills: git-context, openwrt-source-context, embedded-c-code-review, shell-script-review, review-domain-mapping, review-aggregation, review-risk, review-report-render
  • 11 domain skills: 5 protocol (dhcp/pppoe/tr069/mesh/wifi) + 5 web (domain/html/js/cgi/luci) + 2 OpenWrt (build/shell)
  • 5 schemas: agent-registry, review-task, review-plan, review-findings, review-report
  • 4 review modes: diff / commit / module / full
  • 3 output formats: JSON canonical / Markdown / HTML self-contained
  • Routing rules: virtual-file bypass, longest-glob tie-breaker, is_fallback-last
  • OpenWrt tarball: auto fetch + SHA256 verify + apply patches + synthetic diff + virtual path

Mục tiêu

  • Review mã nguồn nhất quán theo domain kỹ thuật (protocol, driver, web)
  • Hỗ trợ nhiều cách chọn phạm vi review: commit mới nhất, N commit gần nhất, commit theo ID, toàn module, PR diff
  • Không bỏ sót file — code không thuộc domain nào vẫn được review bởi fallback agent
  • Dễ mở rộng: thêm agent / skill qua file markdown + registry, không sửa core
  • Output chuẩn hóa theo JSON schema — có thể tích hợp CI/gate

Tại sao openwrt-build-review-agent đứng riêng?

Domain agent (DHCP/PPPoE/…) review logic giao thức. openwrt-build review vỏ bọc của package — Makefile, patches, script init/system, /lib/functions.sh. Hai tầng hoàn toàn khác: cùng 1 commit bump PKG_VERSION có thể đụng cả Makefile (build agent review) lẫn source trong tarball (domain agent review, qua openwrt-source-context-skill sinh synthetic diff). Hai agent chạy song song, ghép findings ở Bước 8.

Nguyên tắc thiết kế

Separation of Concerns

Orchestrator điều phối, agents review chuyên sâu, skills cung cấp tri thức. Mỗi layer có trách nhiệm rõ, không chồng chéo.

Schema-driven

Giao tiếp giữa các thành phần qua JSON schema (task / plan / findings). Thay đổi nội dung không phá contract.

Extensibility

Thêm agent / skill mới qua markdown + registry entry. Core orchestrator không cần sửa khi mở rộng domain.

No missed file

Mọi file trong scope đều có agent review. File không match domain → fallback tới generic-review-agent.

Đồng nhất mọi Agent

Tất cả 8 agent tuân theo cùng một contract và workflow skeleton:

  • Nhận review-task (scope_files + objective + focus_tags)
  • Review trong phạm vi được cấp
  • Áp dụng core skill + domain skill tương ứng
  • Trả review-findings (severity / evidence / impact / recommendation / confidence)

Agent phức tạp (như Web) có nhiều loại file con — nhưng vẫn giữ workflow skeleton này; chỉ thêm bước phân loại file bên trong để delegate sang sub-skill phù hợp. Về mặt kiến trúc, Web Agent có shape giống các agent khác.

Commit Selection (commit-review)

commit_spec là object linh hoạt hỗ trợ nhiều use case:

Use caseUser yêu cầucommit_spec
Commit gần nhất"review commit gần nhất"{ref:"HEAD", count:1}
N commit gần nhất"review 3 commit gần nhất"{ref:"HEAD", count:3}
Commit thứ K gần nhất"review commit thứ 2 gần nhất"{ref:"HEAD~1", count:1}
Commit cụ thể"review commit abc123"{ref:"abc123", count:1}
N commit từ hash"review 2 commit từ abc123"{ref:"abc123", count:2}

Quy ước "commit thứ K gần nhất"

Vị tríGit ref
Thứ 1 gần nhấtHEAD
Thứ 2 gần nhấtHEAD~1
Thứ K gần nhấtHEAD~(K-1)
Giới hạn
  • count ∈ [1, 10]. Yêu cầu > 10 sẽ bị reject.
  • ref phải resolve được (hash tồn tại, HEAD~N trong depth của repo).
  • aggregation:"combined" (mặc định): 1 diff tổng cho cả range, 1 review pass.
  • aggregation:"per-commit": review mỗi commit riêng, findings tách theo commit.

Orchestrator

Điều phối toàn bộ phase code review

Vai trò

review-orchestrator nhận review request, lập kế hoạch, phân công các sub-agent, tổng hợp kết quả thành report cuối. Đây là điểm vào duy nhất của framework từ phía user/CI.

Workflow 10 bước

Context Extraction: (0.1) gọi git-context-skill resolve commit_spec / liệt kê module files. (0.2) detect OpenWrt package pattern (Makefile có PKG_SOURCE + PKG_HASH) → gọi openwrt-source-context-skill để fetch + verify tarball, apply patches, sinh synthetic diff + virtual files.
Change Understanding: đọc diff / changed_files / commit messages, tóm tắt intent, xác định domain chính/phụ.
Domain Mapping (3 giai đoạn):
2.a Virtual files (có virtual_source) → match theo basename trigger / extension, bypass allowed_paths.
2.b File git thật → path match, tie-breaker: longest-glob wins → extension-qualified → domain agent > build agent. Skip agent có is_fallback: true.
2.c Fallback: web extension → web-review-agent; shell OpenWrt path → openwrt-build-review-agent; shell khác → generic-review-agent; C → generic-review-agent; còn lại → unclassified_files.
Ghi routing_decisions[] vào plan để audit.
Unclassified Handling: gán generic-review-agent cho unclassified_files. Nếu ≥ 3 files cùng pattern → emit suggested_new_agents.
Strategy Selection: chọn strategy phù hợp mode. Gắn focus_tags (security, performance, state-machine, …).
Task Decomposition: chia thành các task theo logic kỹ thuật (protocol correctness, state transitions, memory, …).
Agent Selection: assign agent từ agent-registry.yaml cho mỗi task.
Scope Control: cấp context tối thiểu — không cho agent đọc toàn repo.
Aggregation: merge findings từ agents, dedupe, group theo severity/domain.
Gap Detection + Final Output: kiểm tra missing tests / backward compat / performance. Build aggregated report (theo review-report.schema.json) với verdict + top_findings, sau đó gọi review-report-render-skill để ghi .review/<review_id>/ (meta.json, plan.json, report.json/md/html, findings/). Chi tiết ở trang Output & Artifacts.

Guardrails

  • Không review từng dòng code; không viết fix
  • Chỉ assign agent có trong registry
  • Validate commit_spec.count ∈ [1, 10]
  • File không match domain → phải assign generic-review-agent, không bỏ qua
  • Mọi output phải đúng JSON schema

Core Skills

git-context-skill

Mục đích: Trích xuất context từ git — resolve commit_spec hoặc liệt kê module files. Là bước đầu tiên khi mode = commit-review hoặc module-review.

Input: commit_spec (ref, count, aggregation) hoặc module_path.

Output: diff_content, commits[] metadata, changed_files hoặc scope_files.

Validation: count ∈ [1,10]; ref resolve được; repo depth đủ.

openwrt-source-context-skill v0.1.0

Mục đích: Xử lý pattern OpenWrt khi source nằm trong tarball dl/*.tar.gz, git chỉ track Makefile + patches + overlay. Bổ sung git-context-skill, được orchestrator gọi ở Bước 0.

4 case xử lý:

  • A: Commit bump PKG_VERSION → fetch 2 tarball → apply patches → synthetic diff (tarball cũ vs mới)
  • B: Commit sửa patch → apply patches-before + patches-after → diff 2 state = diff ngữ nghĩa của patch
  • C: Mixed (Makefile + patches cùng commit)
  • D: Module review — extract + apply tất cả patches → full scope

Security: verify SHA256 khớp PKG_HASH trước khi extract (tránh supply chain), tar-slip protection, không chạy script từ tarball.

Cache: .review/.cache/sources/<pkg>/<ver>-<hash7>/, LRU, atomic extract qua tmp rename.

Virtual path: file trong tarball dùng path virtual (apps-1.2.4/src/main.c) + metadata virtual_source để trace.

Chi tiết: xem trang OpenWrt tarball source.

shell-script-review-skill v0.1.0

Mục đích: Checklist shell generic (POSIX sh, BusyBox ash, bash) cho bất kỳ file .sh nào trong scope review. Được dùng bởi openwrt-build-review-agent (kèm openwrt-shell-domain-skill) và generic-review-agent (fallback).

Bug categories:

  • Portability: bashism trong script shebang sh ([[ ]], array, <<<, ${var^^})
  • Quoting: unquoted var trong rm/mv, word splitting, IFS không restore
  • Error handling: set -e pitfall, pipeline không pipefail, cd || exit
  • TOCTOU: predictable tempfile (symlink attack), check-then-use race, rm -rf "$var/" khi var rỗng
  • Injection: eval, command substitution với untrusted input, path traversal
  • Anti-patterns: UUOC, ls parse, echo với flag, subshell vô ý

Cross-reference: mapping tới ShellCheck rules (SC2086, SC2164, SC2115…) để reviewer đối chiếu nhanh.

embedded-c-code-review-skill

Mục đích: Checklist dùng chung cho review C/C++ embedded. Bắt buộc include trong mọi agent review C code.

Nội dung: 9 category — pointer/bounds, integer, memory ownership, timer/callback lifecycle, error path, restart/reload, hot path, backward compat, concurrency.

Severity mapping: NULL deref exploitable → critical; missing NULL check input → major; log verbose in hot path → minor.

review-domain-mapping-skill

Mục đích: Map file → domain → agent. Là bước 2 của orchestrator.

Algorithm 4 bước: (1) path match allowed_paths → (2) trigger keyword match → (3) extension match cho web → (4) fallback tới generic-review-agent.

Pattern detection: nếu ≥ 3 unclassified files cùng subdirectory → emit suggested_new_agents.

review-aggregation-skill

Mục đích: Merge findings từ nhiều sub-agent thành report thống nhất.

Rules: Dedupe theo (file, function, title, impact); giữ severity cao hơn; group theo severity → domain → file; phân loại must-fix / should-fix / observation.

Per-commit mode: giữ findings riêng theo commit hash, cho phép truy xuất theo commit.

review-risk-skill

Mục đích: Đánh giá risk cross-cutting ngoài findings.

6 risk categories: regression, backward compatibility, restart/reload lifecycle, memory/resource, performance/latency, security exposure.

Output: risk_summary với level (high/medium/low/none) + mitigation_needed.

review-report-render-skill

Mục đích: Chuyển review-report.schema.json thành artifacts người đọc được (Markdown + HTML self-contained) và chuẩn hoá thư mục / đặt tên file output. Là bước cuối của orchestrator (10.2).

Verdict logic

Tính tự động từ stats + confidence:

Điều kiệnVerdict
≥ 1 finding critical (bất kỳ confidence)🔴 block
≥ 1 finding major với confidence = high🔴 block
Còn lại có major / minor🟠 needs-fix
Chỉ có info hoặc zero findings🟢 ship

verdict_rationale: 1 câu ngắn giải thích quyết định — ví dụ "2 critical (DHCP-001, DHCP-004) + 1 major confidence=high (WEB-CGI-002)".

Top Findings ranking

Rank findings theo score, lấy top 5-10 và lưu id vào top_findings[]:

score = severity_weight × confidence_weight × category_weight

severity_weight:   critical=100, major=40, minor=10, info=1
confidence_weight: high=1.0, medium=0.7, low=0.4
category_weight:   security=1.3, correctness=1.1, reliability=1.0,
                   compat=0.9, performance=0.8, style=0.5

Logic đảm bảo: security critical high đứng đầu, style minor low đứng cuối. Người đọc mở report.md là thấy ngay 5-10 finding quan trọng nhất.

Markdown template — thứ tự section cố định

Thứ tự section trong report.md là hard contract — downstream bot có thể grep section header mà không lo format đổi:

  1. Header (title + verdict badge + stats)
  2. Scope (commits / module / files / focus_tags)
  3. TL;DR (summary 3-5 dòng)
  4. Top Findings (render đầy đủ code snippet)
  5. Findings by Severity (Critical → Info, dùng <details> collapse)
  6. Findings by Domain (bảng với agent + count)
  7. Risk Summary
  8. Missing Tests (checkbox list, link related_findings)
  9. Human Attention
  10. Suggested New Agents
  11. Footer (generator version + artifacts list)

Module-review vs Commit-review

Module-review tốn nhiều tài nguyên hơn (scan toàn bộ code), dùng cho audit định kỳ hoặc pre-release. Commit-review focus vào regression risk của thay đổi mới, dùng cho CI/PR gate.

OpenWrt tarball source

Review package có source trong dl/*.tar.gz

Vì sao cần xử lý riêng?

Package OpenWrt thường không commit source code trực tiếp vào git. Thay vào đó:

package/network/services/apps/
├── Makefile                ← PKG_SOURCE, PKG_VERSION, PKG_HASH
├── patches/                ← áp lên tarball extract
│   ├── 001-fix-bug.patch
│   └── 002-feature.patch
└── files/                  ← overlay (init, uci-defaults, hotplug)

dl/
└── apps-1.2.4.tar.gz       ← KHÔNG trong git, source thực tế ở đây

Khi review commit bump version hoặc sửa patch, diff git chỉ cho thấy meta-diff (đổi 1 dòng PKG_VERSION, hoặc diff của patch file) — không phản ánh đúng thay đổi code thực. Framework cần extract tarball + apply patches để so sánh.

4 case xử lý

Case A — Commit chỉ bump PKG_VERSION

→

→

→

Synthetic diff thể hiện đúng thay đổi upstream giữa 2 version, đã loại patches (vì patches được apply lên cả 2).

Case B — Commit sửa/thêm patch

patches/003-new.patch
→
extract tarball
→
apply patches-before
→
apply patches-after
→
diff ngữ nghĩa

Thay vì nhìn vào diff của patch file (meta-diff khó đọc), ta so sánh 2 state source — trực quan như commit thường.

Case C — Mixed (Makefile + patches cùng commit)

Kết hợp logic Case A + B: dùng Makefile mới + patches mới, Makefile cũ + patches cũ.

Case D — Module review OpenWrt package

Mode module-review: extract tarball hiện tại, apply tất cả patches → full scope_files cho agent audit toàn bộ.

Security guardrails

  • Hash verify trước khi extract — tránh supply chain attack khi URL bị MITM
  • Tar-slip protection — không extract file symlink / path trỏ ra ngoài extract dir
  • Không chạy code từ tarball — không invoke configure/Makefile/build script
  • Atomic extract — qua .tmp-<pid>/ rồi rename
  • Size cap — skip file binary quá lớn, chỉ extract theo glob review-able

Cache

.review/.cache/sources/
├── _index.json                    LRU, size tracking
└── apps/
    ├── 1.2.3-def5678/
    │   ├── .source/               raw extract
    │   └── .patched/              sau apply patches
    └── 1.2.4-abc1234/
        ├── .source/
        └── .patched/

Cache key: (PKG_NAME, PKG_VERSION, PKG_HASH[:7]). Default cap 2GB, cấu hình qua env REVIEW_CACHE_MAX_MB. LRU evict khi đầy.

Fetch strategy

Thử tuần tự, dừng khi thành công:

  1. <repo_root>/dl/<PKG_SOURCE> — nếu user đã download sẵn
  2. $REVIEW_DL_MIRROR/<PKG_SOURCE> — local mirror
  3. $PKG_SOURCE_URL/<PKG_SOURCE> — network
  4. OpenWrt macro: @APACHE/, @GNU/, @SF/
  5. Fail → report "tarball not available offline" + fallback review build-level only

Giới hạn hiện tại
  • Chưa hỗ trợ PKG_SOURCE_PROTO:=git / svn / hg — roadmap cần openwrt-git-source-skill

  • Tarball lớn (kernel > 100MB) cần network lần đầu + disk cache
  • Patch conflict → skip patch đó + log warning, không tạo synthetic diff cho phần conflict
